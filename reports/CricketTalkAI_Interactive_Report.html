End-to-End Training & Architecture Pipeline Implementation Details

Figure 2: Architectural workflow from raw scenario synthesis through QLoRA training and Gradio deployment.

Assistant Response Masking

Using custom token-offset mapping, cross-entropy training loss was computed exclusively on the assistant's generated tokens. All prompt tokens (system prompt, user inquiry, and role headers) were masked with label -100, ensuring the model learned commentary generation rather than memorizing prompt prefixes.

Disjoint Split Verification

To prevent test set contamination, data was split by Scenario ID rather than random row partitioning. Automated disjoint-set set intersection tests verified 0% scenario leakage and 0% question overlap between the 660 training records and the 20 validation / 20 test splits.

Limitations, Threats to Validity & Future Research Critical Appraisal
  • Regex Lexicon Heuristic Boundary: The quantitative style score (75.0%) was derived from a strict regex lexicon matching canonical cricket terms (wicket, pitch, innings, bowler, batter, boundary, umpire, fielder, over, run, six, stumps, defense). While highly reliable against false positives, it does not detect conversational commentary cadence that avoids explicit jargon.
  • Holdout Sample Size: While the 20-question test split was strictly partitioned by Scenario ID to ensure zero data leakage, a benchmark of 200+ instances evaluated via multi-judge LLM-as-a-judge or human double-blind panels would offer narrower confidence intervals.
  • Prompted Base Model Verbosity: Under zero-shot prompting, the 0.5B base model exhibited severe verbosity, exhausting the 256-token ceiling on 90% of prompts. This demonstrates that prompting alone is insufficient for compact instruction-following in sub-billion parameter models.
  • Private Adapter Access: The Hugging Face adapter remains under private access controls (Hiteshilamakar23/crickettalk-ai-lora). Environment variable authentication via HF_TOKEN is required for replication.
